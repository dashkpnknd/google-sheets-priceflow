# Краснодар — ru:Store

Готовый Google Apps Script для Краснодарской таблицы. Он не входит в Telegram и не хранит Telegram-сессию: раз в 15 минут получает защищённый JSON-снимок сообщений и обновляет только цены совпавших объявлений в таблице `Краснодар | ru:Store`.

## Установка

В Apps Script, связанный с таблицей цен Краснодара, скопировать только:

1. `RuStoreCatalog.gs` как Script;
2. `RuStoreCatalogSidebar.html` как HTML.

Обновить таблицу, открыть меню **«Каталог ru:Store»** и нажать **«Сохранить и выполнить первую синхронизацию»**. Никакие адреса, каналы или секреты в панели не вводятся: источник и целевая таблица объявлений Краснодар уже заданы внутри проекта.

Синхронизация не создаёт, не удаляет и не редактирует ассортимент. Она меняет только `Price` в листе мобильных объявлений. Совпадение требует модели, памяти, цвета и SIM; для Android также RAM. Если позиция или цена поставщика неоднозначны, она не записывается и остаётся в отчёте выполнения.

## Серверный источник

`GET` endpoint с заголовком `X-PriceFlow-Secret` должен вернуть HTTP 200 и JSON:

```json
{"posts":[{"id":"123","text":"полный актуальный текст прайс-поста","updatedAt":"2026-08-20T00:00:00Z"}]}
```

Сервис уже настроен на единственный канал read-only аккаунта — **Прайс ru:Store новый** (проверено по точному названию в Telegram). Он каждые 15 минут перечитывает до 1000 сообщений канала, поэтому учитывает изменение старых прайс-постов, а не ждёт новых сообщений. В GitHub нельзя хранить `api_id`, `api_hash`, Telegram session или секрет endpoint.

## Однократная QR-авторизация Telegram

В `server/` лежит готовый Docker-контейнер `telegram-qr-login`. `TG_API_ID` и `TG_API_HASH` передаются контейнеру только командой запуска и не сохраняются в файле на сервере. Контейнер создаёт одноразовый QR-код; его сканируют в Telegram: **Настройки → Устройства → Подключить устройство**. Сессия остаётся в Docker volume `telegram-session` и не попадает в GitHub или таблицу.

Если QR-вход недоступен, предусмотрен одноразовый вход по коду: сервер запрашивает код для согласованного номера, затем оператор вводит его в закрытом сеансе. Код и короткоживущий `phone_code_hash` не попадают в GitHub, таблицу или логи и удаляются после успешного входа.

## Правила

- Разбираются товарные строки формата «название — цена». Формат объёмных цен `1 шт / 3+ / 5+` не используется для Краснодара и намеренно пропускается: это правило другого клиентского проекта.
- Наценки и округления отсутствуют. В таблицу пишется исходное число, например `71800`, с форматом `0`.
- Флаг и страна сохраняются для всех распознанных стран, в том числе `🇪🇺` → `Европа 🇪🇺`; память, цвет и SIM также сохраняются. `eSim` нормализуется до `eSIM`, `Sim+eSim` — до `SIM + eSIM`.
- Строки без цены, с ценой, помеченной `?`, и информационные посты не превращаются в товары. При следующей пересборке отредактированная строка с подтверждённой ценой будет записана.
