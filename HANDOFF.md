# PriceFlow — передача проекта

Этот репозиторий содержит Google Apps Script-продукты для автоматической выгрузки ассортимента и цен в клиентские Google Таблицы.

## Рабочие клиентские реализации

Это не два обезличенных продукта: сейчас репозиторий содержит **две отдельные клиентские реализации**. Не переносить настройки одной в другую без проверки.

| Клиентская папка | Интеграция | Источник | Канонические исходники | Что делает |
| --- | --- | --- | --- | --- |
| `Ульяновск/Telegram/` | Telegram | Публичный канал `@opt_uniseil` | `Ульяновск/Telegram/` | Пересобирает каталог поставщика в товарных листах и применяет правила Ульяновска |
| `Москва/МойСклад/` | МойСклад | API МоегоСклада | `Москва/МойСклад/` | Пересобирает каталог из МоегоСклада и применяет правила Москвы |

Папки клиента — единственная точка входа для следующего разработчика: в них находятся код, панель, тесты и клиентские правила. Папка `outputs/` содержит только архивы и ранние прототипы.

Остальные папки и файлы в `outputs/` — ранние прототипы, архивы ZIP или отдельные эксперименты. Не смешивать их с двумя продуктами выше при установке клиенту.

## Структура каждого продукта

### Ульяновск — Telegram

- `TelegramCatalog.gs` — серверная логика Apps Script: загрузка публичного канала, разбор товаров, маршрутизация по листам, автозапуск и отчёт.
- `TelegramCatalogSidebar.html` — боковая панель подключения: магазин/город, канал, кнопки подключения и ручной пересборки.
- `test-telegram-catalog.mjs` — автоматические тесты разбора и маршрутизации.
- `README.md` — краткая установка для таблицы клиента.

Текущий профиль разбора настроен на `@opt_uniseil`. Для канала с другой структурой сообщения меняются только правила разбора в `tcParsePost_`, `tcLine_` и `tcExpand_`; интерфейс и остальные компоненты сохраняются.

Нельзя потерять следующие особенности Ульяновска:

- страна хранится в отдельной колонке вместе с флагом;
- создаётся отдельная строка `2 SIM` по цене `SIM + eSIM`, если в панели включён переключатель;
- применяется наценка из файла правил клиента;
- для одинаковой модели/конфигурации/памяти/цвета выбирается подходящая самая дешёвая позиция поставщика;
- значения записываются текстом, а не требуют совпадения с выпадающими списками исходной таблицы.

### Москва — МойСклад

- `MoySkladCatalog.gs` — серверная логика Apps Script: API МоегоСклада, разбор названий, маршрутизация и автозапуск.
- `MoySkladCatalogSidebar.html` — боковая панель с полем «Магазин | Город» и API-токеном.
- `test-moysklad-catalog.mjs` — автоматические тесты категорий, атрибутов и записи.
- `README.md` — краткая установка.

Нельзя потерять следующие особенности Москвы:

- телефоны Apple и Android распределяются в два товарных блока листа `телефоны`;
- ноутбуки, планшеты, часы, наушники, приставки, Dyson и iMac направляются в соответствующие листы;
- текущая версия сохранена без новой маршрутизации аксессуаров: кроме наушников они пока остаются в листе `телефоны`;
- EarPods/AirPods и другие наушники остаются на листе `наушники`;
- токен хранится только в `Script Properties`, не в ячейках и не в репозитории;
- после подключения устанавливается триггер раз в 15 минут.

## Стандартные клиентские листы

Обычный набор листов:

`телефоны`, `аксессуары`, `макбуки`, `аймаки`, `айпады`, `часы`, `наушники`, `пс`, `дайсон`.

В Telegram-версии ассортимент пишется в товарные листы, не создавая отдельный лист с сырой выдачей. В версии МоегоСклада действует то же правило.

## Важные правила безопасности

Никогда не коммитить:

- API-токены МоегоСклада;
- таблицы/экспорты с клиентскими данными;
- скриншоты с токенами;
- `appsscript.json`, если в него случайно добавлены секреты.

В GitHub должны попадать только код, тесты, README и этот handoff.

## Проверка перед передачей клиенту

В папке каждого продукта выполнить:

```bash
node test-telegram-catalog.mjs
node test-moysklad-catalog.mjs
```

Команда запускается из соответствующей папки. Также проверять Apps Script:

1. В панели подключить источник и дождаться первого результата.
2. В Apps Script открыть «Триггеры» — должен быть один активный триггер нужного продукта.
3. Открыть «Выполнения» — `syncTelegramCatalog` или `syncMoySkladCatalog` должны завершаться успешно примерно раз в 15 минут.
4. Не оставлять старые триггеры вроде `syncAllProjects`: они создают ложные ошибки и дублирующие запуски.

## Отложенная следующая задача: Москва / МойСклад

Для московского проекта МоегоСклада пользователь создал лист `аксессуары`. Следующий чат должен реализовать: в листе/Android-блоке `телефоны` должны оставаться только реальные телефоны. Чехлы, стекла, кабели, зарядки, адаптеры, держатели, ремешки, powerbank, аксессуары для приставок и аналогичные товары направлять на `аксессуары`. Наушники направлять в `наушники`.

**Эта задача намеренно не реализована в текущей версии.** Код оставлен в исходной рабочей конфигурации по просьбе пользователя; не считать лист `аксессуары` подключённым только из-за его наличия в таблице. Перед внедрением изменить `Москва/МойСклад/MoySkladCatalog.gs`, добавить/обновить тесты и один раз запустить «Пересобрать каталог сейчас»: это очистит прежние неправильно попавшие аксессуары из блока телефонов и запишет их в новый лист.

## Рекомендуемая работа с GitHub

Создать **один приватный репозиторий**, например `priceflow-google-sheets`.

В нём хранить клиентские реализации отдельными папками верхнего уровня. Следующие три проекта добавлять по такому же принципу, не смешивая индивидуальные правила:

```text
Ульяновск/
  Telegram/
    README.md                  # правила клиента и установка
Москва/
  МойСклад/
    README.md                  # правила клиента и установка
<Новый город>/
  Telegram/ или МойСклад/
HANDOFF.md
```

Один репозиторий даёт общую историю, единые тесты и простую передачу в другой чат. Отдельные репозитории нужны только если продукты будут продаваться и развиваться полностью независимо разными командами.

## Как продолжить в новом чате Codex

Передать ссылку на репозиторий и написать:

> «Прочитай `HANDOFF.md` и `[город]/[интеграция]/README.md`. Работаем только с этим клиентом. Сначала проверь тесты и не меняй другой проект без отдельного запроса».

Так новый чат начнёт с актуальной структуры и не будет использовать устаревшие файлы из `outputs/`.
