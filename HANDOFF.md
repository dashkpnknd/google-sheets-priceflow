# PriceFlow — передача проекта

Этот репозиторий содержит Google Apps Script-продукты для автоматической выгрузки ассортимента и цен в клиентские Google Таблицы.

## Обязательное правило работы

Нельзя самостоятельно придумывать, расширять или изменять бизнес-правила, ценовые диапазоны, исключения, маршрутизацию или формат данных. Выполнять только явно сформулированные пользователем требования. Если для случая нет прямого правила, остановиться и запросить уточнение; не подставлять «логичное» предположение. После каждого изменения обновлять этот `HANDOFF.md` и передавать пользователю готовый файл кода для копирования в Apps Script.

## Рабочие клиентские реализации

Это не единый обезличенный продукт: в репозитории есть отдельные клиентские реализации. Не переносить правила одного клиента в другой без проверки.

| Клиентская папка | Интеграция | Источник | Канонические исходники | Что делает |
| --- | --- | --- | --- | --- |
| `Ульяновск/Telegram/` | Telegram | Публичный канал `@opt_uniseil` | `Ульяновск/Telegram/` | Пересобирает каталог поставщика в товарных листах и применяет правила Ульяновска |
| `Москва/МойСклад/` | МойСклад | API МоегоСклада | `Москва/МойСклад/` | Пересобирает каталог из МоегоСклада и применяет правила Москвы |
| `Электросталь/Telegram/` | Telegram | Публичный прайс `@astoredirectprice` | `Электросталь/Telegram/` | Пересобирает каталог поставщика с индивидуальными наценками Электростали |
| `Краснодар/RuStore/` | Telegram (приватный) | `Прайс ru:Store новый` | `Краснодар/RuStore/` | Серверный read-only клиент, HTTPS-снимок и Apps Script-парсер |
| `Орск/RMGroup/` | RM Group Client API | `https://api-c.rmgroup.website/` | `Орск/RMGroup/` | Получает `pricelist.get` и пересобирает каталог после подключения токена |

Папки клиента — единственная точка входа для следующего разработчика: в них находятся код, панель, тесты и клиентские правила. Папка `outputs/` содержит только архивы и ранние прототипы.

### Орск — Яблочный Спас / RM Group

- `Орск/RMGroup/RMGroupCatalog.gs` — Apps Script для RM Group Client API.
- `Орск/RMGroup/RMGroupCatalogSidebar.html` — подключение токена и первая синхронизация.
- `Орск/RMGroup/test-rmgroup-catalog.mjs` — тесты официальной структуры `pricelist.get`.
- `Орск/RMGroup/README.md` — установка.

Техническая часть подготовлена 2026-08-22 без реального токена и без таблицы. Официальный API работает единственным POST-адресом `https://api-c.rmgroup.website/`, заголовок авторизации — `Auth`, запрос — `{"method":"pricelist.get"}`. Прайс доступен с 11:00 до 18:00 МСК; вне этого времени ожидается HTTP 425. Токен при подключении проверяется до сохранения и хранится только в Script Properties. Создаётся ровно один триггер `syncRMGroupCatalog` раз в 15 минут. Поля API `brand`, `category`, `subcategory`, `id`, `name`, `country`, `cost` разобраны в стандартные товарные листы. Ценовая наценка/округление не реализованы намеренно: пользователь пока не задавал правила, поэтому API-цена записывается без изменений. Для запуска нужны только выданный командой RM Group токен и ссылка на Google-таблицу с обычными листами клиента.

Остальные папки и файлы в `outputs/` — ранние прототипы, архивы ZIP или отдельные эксперименты. Не смешивать их с двумя продуктами выше при установке клиенту.

## Структура каждого продукта

### Ульяновск — Telegram

- `TelegramCatalog.gs` — серверная логика Apps Script: загрузка публичного канала, разбор товаров, маршрутизация по листам, автозапуск и отчёт.
- `TelegramCatalogSidebar.html` — боковая панель подключения: магазин/город, канал, кнопки подключения и ручной пересборки.
- `test-telegram-catalog.mjs` — автоматические тесты разбора и маршрутизации.
- `README.md` — краткая установка для таблицы клиента.

Текущий профиль разбора настроен на `@opt_uniseil`. Для канала с другой структурой сообщения меняются только правила разбора в `tcParsePost_`, `tcLine_` и `tcExpand_`; интерфейс и остальные компоненты сохраняются.

Нельзя потерять следующие особенности Ульяновска:

- страна хранится в отдельной колонке вместе с флагом;
- создаётся отдельная строка `2 SIM` по цене `SIM + eSIM`, если в панели включён переключатель;
- применяется наценка из файла правил клиента;
- для одинаковой модели/конфигурации/памяти/цвета выбирается подходящая самая дешёвая позиция поставщика;
- значения записываются текстом, а не требуют совпадения с выпадающими списками исходной таблицы.

### Москва — МойСклад

- `MoySkladCatalog.gs` — серверная логика Apps Script: API МоегоСклада, разбор названий, маршрутизация и автозапуск.
- `MoySkladCatalogSidebar.html` — боковая панель с полем «Магазин | Город» и API-токеном.
- `test-moysklad-catalog.mjs` — автоматические тесты категорий, атрибутов и записи.
- `README.md` — краткая установка.

Нельзя потерять следующие особенности Москвы:

- телефоны Apple и Android распределяются в два товарных блока листа `телефоны`;
- ноутбуки, планшеты, часы, наушники, приставки, Dyson и iMac направляются в соответствующие листы;
- аксессуары (чехлы, стёкла, кабели, зарядки, адаптеры, держатели, ремешки, powerbank и игровые аксессуары) направляются в `аксессуары`, а реальные телефоны остаются в `телефоны`;
- EarPods/AirPods и другие наушники остаются на листе `наушники`;
- токен хранится только в `Script Properties`, не в ячейках и не в репозитории;
- после подключения устанавливается триггер раз в 15 минут.

### Краснодар — RuStore

- `RuStoreCatalog.gs` — Apps Script: получает защищённый JSON-снимок прайс-постов и пересобирает товарные листы раз в 15 минут.
- `RuStoreCatalogSidebar.html` — панель настройки адреса HTTPS-снимка и секрета; секрет хранится только в Script Properties.
- `test-rustore-catalog.mjs` — тесты парсинга, стран/SIM, цен, пропусков и маршрутизации.
- `README.md` — установка и контракт серверного снимка.

На листе `телефоны` Краснодар использует два существующих блока: левый — iPhone, правый — все Android-телефоны. Все распознанные Android-бренды (`Samsung/Galaxy`, Pixel, Xiaomi/Redmi, Honor, Huawei, OnePlus, realme, OPPO, vivo) направляются вправо. Другие товарные листы не меняются.

У актуального Samsung-поста `Прайс ru:Store новый` заголовок начинается с `🤖 SAMSUNG`. Эмодзи `🤖` обязательно удаляется до распознавания заголовка; иначе строки `S26 …` теряют марку, попадают в `прочее` и не записываются в правый Android-блок. Строки с `?` после цены по-прежнему не записываются.

Краснодарский источник — единственный приватный канал read-only Telegram-аккаунта: **Прайс ru:Store новый**. Это фактическое точное имя, полученное из списка диалогов авторизованного Telegram-аккаунта. Apps Script не входит в Telegram и не хранит Telegram-сессию. Серверный клиент каждые 15 минут перечитывает до 1000 сообщений (включая старые отредактированные прайс-посты) и отдаёт Apps Script JSON вида `{"posts":[{"id":"…","text":"…"}]}` по HTTPS с заголовком `X-PriceFlow-Secret`.

Подготовлен `Краснодар/RuStore/server/` для одноразовой QR-авторизации Telegram. До показа QR нужны только `TG_API_ID` и `TG_API_HASH` от Telegram API-приложения; они передаются контейнеру только при запуске и не записываются ни в Git, ни в файл на сервере. Сессия хранится только в Docker volume сервера.

Для Краснодара нет наценки, округления, схемы «2 SIM» или выбора самой дешёвой позиции. Цена из товарной строки записывается исходным числом в формате `0`. Поддерживается формат «название — цена»; строки объёмной цены `1 шт / 3+ / 5+` намеренно пропускаются, поскольку это правило другого клиентского проекта. Строки без цены или с `?` после цены не становятся товарами и пропускаются только при текущей пересборке; если поставщик затем добавит подтверждённую цену, та же отредактированная строка будет добавлена. Сохраняются все флаги и страны; `🇪🇺` записывается как `Европа 🇪🇺`.

### Электросталь — Telegram

- `TelegramCatalog.gs`, `TelegramCatalogSidebar.html`, `test-telegram-catalog.mjs`, `README.md` — отдельная реализация, не смешивать с Ульяновском.
- Источник — текстовый прайс `@astoredirectprice`; флаг и страна сохраняются в отдельной колонке.
- Apple: 5–15 тыс. +3 000; 16–35 +4 000; 36–69 +5 000; 70–89 +6 000; 90–110 +7 500; 111–150 +9 000; 151–225 +13 000 ₽.
- Samsung/Android: 5–15 тыс. +3 000; 16–35 +5 000; 36–69 +7 000; 70–89 +8 000; 90–110 +8 500; 111–150 +10 000; 151–225 +15 000 ₽.
- **Все остальные категории** используют шкалу Samsung/Android. После любой наценки цена округляется вверх до ближайших 500 ₽ и записывается числом в формате `0`.
- Цены ниже 5 тыс. ₽ не получают наценку. Для цены выше 225 тыс. ₽ применяется `+15 000` для любой категории, затем округление вверх до 500 ₽. Пометки поставщика `(Active)` и `(Уценка)` сохраняются в начале названия, даже если они стоят перед `iPhone`.
- Актуальный формат `@astoredirectprice`: статусы поставщик пишет в конце строки без скобок — `Актив` и `Уценка`; в таблицу они записываются в начале названия как `(Актив)` и `(Уценка)`. Заголовок раздела может быть `Apple · iPhone …`; его нужно распознавать как контекст iPhone.

## Стандартные клиентские листы

Обычный набор листов:

`телефоны`, `аксессуары`, `макбуки`, `аймаки`, `айпады`, `часы`, `наушники`, `пс`, `дайсон`.

В Telegram-версии ассортимент пишется в товарные листы, не создавая отдельный лист с сырой выдачей. В версии МоегоСклада действует то же правило.

## Единый формат цветов для автозагрузки Avito

Во всех клиентских продуктах (`Ульяновск`, `Москва`, `Электросталь`, `Краснодар`, `Орск`) значение записывается в отдельную колонку `Color`/`Цвет` только в формате эталонной автозагрузки Avito. Разрешены исключительно: `бежевый`, `белый`, `голубой`, `зеленый`, `золотистый`, `желтый`, `красный`, `оранжевый`, `розовый`, `серебристый`, `серый`, `синий`, `фиолетовый`, `черный`. Название товарной строки поставщика не менять.

Соответствие определяется по модели и её вариантам в эталонной автозагрузке, а не только по схожести названий: например, `Lavender` у iPhone 17 — `фиолетовый`, `Sage` — `зеленый`, `Natural Titanium` у iPhone 16 Pro — `серый`, `Desert Titanium` — `золотистый`, а синий оттенок iPhone 17 Pro — `синий`, не `голубой`. Фирменные названия, которых ещё нет в утверждённом соответствии, не заменять по догадке: сначала сверить с моделью в эталонной автозагрузке и при отсутствии однозначного варианта запросить решение пользователя.

## Орск — формат ответа RM Group

`pricelist.get` у RM Group может вернуть как прежние блоки `{items:[...]}`, так и актуальный прямой массив товаров в `result`. Обработчик обязан поддерживать оба формата; иначе при действующем токене панель показывает ложные `0 позиций`. Сверка 23 августа 2026: актуальный ответ содержит 929 товаров, из которых 816 распределяются по стандартным листам.

В названиях Samsung использовать полную модель из `subcategory`: например, `Galaxy A57 8/256 Gray`, а не `A57 8/256 Gray`. Память `1TB` и `2TB` у iPhone записывается как `1 ТБ` и `2 ТБ`. В текущем прайсе безопасно распределены Poco/Nothing Phone → `телефоны`, Poco Pad → `айпады`, JBL/Harman/Marshall → `наушники`, Nintendo/Oculus/Steam Deck → `пс`, Mac mini → `макбуки`. Для записи 7 iMac должен существовать лист `аймаки` с шапкой `Title`, `Price`.

Дополнительные листы Орска: `камеры` получает DJI, GoPro, Insta360, Fujifilm и Canon; `колонки` — Яндекс Станции. Ray-Ban и Medicube направляются в `аксессуары`. Сверка текущего прайса после этих правил: все 929 из 929 позиций получают лист назначения.

RM Group не передаёт SIM-конфигурацию отдельным полем и в актуальных названиях телефонов её нет. Оставлять `SimConfig` пустым, пока пользователь не задаст правило по умолчанию; не выводить SIM-конфигурацию по догадке.

## Удаление страны из прайс-листов (24 августа 2026)

Во всех пяти импортёрах — Ульяновск Telegram, Москва МойСклад, Электросталь Telegram, Краснодар RuStore и Орск RM Group — колонка `Country`/`Страна` больше не создаётся и не заполняется. При следующей пересборке скрипт физически удаляет все колонки с таким точным заголовком в каждом листе, затем пересчитывает расположение оставшихся колонок и записывает каталог. Страна может остаться внутренним признаком исходной строки только для разбора или выбора цены, но в Google Sheets не выводится.

## Важные правила безопасности

Никогда не коммитить:

- API-токены МоегоСклада;
- таблицы/экспорты с клиентскими данными;
- скриншоты с токенами;
- `appsscript.json`, если в него случайно добавлены секреты.

В GitHub должны попадать только код, тесты, README и этот handoff.

Никогда не коммитить Telegram `api_id`, `api_hash`, строку сессии, пароль аккаунта, секрет HTTPS-снимка или ссылку-приглашение в закрытый канал. Репозиторий сейчас публичный.

## Проверка перед передачей клиенту

В папке каждого продукта выполнить:

```bash
node test-telegram-catalog.mjs
node test-moysklad-catalog.mjs
```

Команда запускается из соответствующей папки. Также проверять Apps Script:

1. В панели подключить источник и дождаться первого результата.
2. В Apps Script открыть «Триггеры» — должен быть один активный триггер нужного продукта.
3. Открыть «Выполнения» — `syncTelegramCatalog` или `syncMoySkladCatalog` должны завершаться успешно примерно раз в 15 минут.
4. Не оставлять старые триггеры вроде `syncAllProjects`: они создают ложные ошибки и дублирующие запуски.

## Выполненная задача: Москва / МойСклад

Лист `аксессуары` подключён к синхронизации. В `телефоны` попадают только реальные телефоны; чехлы, стёкла, кабели, зарядки, адаптеры, держатели, ремешки, powerbank, док-станции и аксессуары для приставок направляются в `аксессуары`. Наушники, включая AirPods и EarPods, направляются в `наушники`.

Уточнение 23 августа 2026: позиция «Глазурь» (защитное покрытие/стекло), в том числе с текстом «голубая глазурь» или `box`, — аксессуар. Это не название цвета и не подлежит переводу в колонку `Color`. Состояние перед моделью, например `(Active) iPhone 17`, сохраняется в названии и остаётся в левом Apple-блоке листа `телефоны`. Цены из API МоегоСклада приходят в копейках и делятся на 100: телефоны дешевле 1 000 ₽ пропускаются, для аксессуаров текущий порог — от 1 ₽.

Уточнение классификации Samsung: чехлы для AirPods/Buds — `аксессуары`, даже если в названии есть AirPods. Портативные колонки, Galaxy Buds и Galaxy Ring направляются в `наушники`; Galaxy Watch — в `часы`. Позиция Samsung/Galaxy без указанной памяти считается носимым устройством: Watch уже направлен в `часы`, остальные — в `наушники`. Служебная решётка `#` в начале названия товара не выводится в таблицу.

## Текущий следующий шаг: Краснодар / Telegram-клиент

Код Apps Script, парсер, запись в листы, триггер и тесты готовы. Серверный Telegram-сеанс Краснодара успешно авторизован 2026-08-21 через одноразовый код и находится в Docker volume на `/opt/priceflow/krasnodar-telegram`; временный `phone_code_hash` после входа удалён. QR-компонент остаётся как запасной путь, но сейчас не запущен. Сервер `snapshot_server.py` читает только канал `Прайс ru:Store новый` и пересобирает снимок каждые 15 минут. Проверка 2026-08-21 на реальном канале: получено 25 сообщений, разобрано 94 позиции; 11 строк с `?` и 22 строки без цены исключены; у всех 65 позиций с флагами заполнена страна. После авторизации сервис получает только права чтения: не отправляет и не пересылает сообщения, не приглашает людей и не подписывается на другие каналы. Панель Краснодара должна выглядеть как у остальных проектов: в ней нет адресов, каналов, секретов и полей ввода, только кнопки **«Сохранить и выполнить первую синхронизацию»** и **«Пересобрать каталог сейчас»**. Источник уже задан в коде; после копирования двух файлов в Apps Script пользователь нажимает первую кнопку.

Если в панели уже нет полей, но кнопка показывает ошибку «Укажите магазин в формате „Магазин | Город“», значит обновлён только HTML, а `RuStoreCatalog.gs` остался старым. Нужно заменить оба файла; актуальная копируемая версия скрипта также лежит в `outputs/krasnodar-rustore/RuStoreCatalog.txt`.

Проверка после исправления контекста поставщика: не накапливать предыдущую товарную строку как контекст. Иначе страна дублировалась, а память не извлекалась. Теперь одна строка каталога содержит ровно один флаг и одну страну; при нескольких флагах поставщика создаётся отдельная строка для каждой страны. Память без единицы измерения (`128`, `256`, `512`) нормализуется в `ГБ`, а `1TB`/`2TB` — в `ТБ`. Отсутствующий лист (например, `аксессуары` в таблице Краснодара) пропускается без остановки синхронизации остальных листов. Эмодзи перед заголовком iPad распознаются. Реальный снимок: 102 позиции — телефоны 65, айпады 8, наушники 9, пс 4; аксессуары 16 пропускаются, если листа нет. 12 автоматических тестов проходят.

## Рекомендуемая работа с GitHub

Создать **один приватный репозиторий**, например `priceflow-google-sheets`.

В нём хранить клиентские реализации отдельными папками верхнего уровня. Следующие три проекта добавлять по такому же принципу, не смешивая индивидуальные правила:

```text
Ульяновск/
  Telegram/
    README.md                  # правила клиента и установка
Москва/
  МойСклад/
    README.md                  # правила клиента и установка
<Новый город>/
  Telegram/ или МойСклад/
HANDOFF.md
```

Один репозиторий даёт общую историю, единые тесты и простую передачу в другой чат. Отдельные репозитории нужны только если продукты будут продаваться и развиваться полностью независимо разными командами.

## Как продолжить в новом чате Codex

Передать ссылку на репозиторий и написать:

> «Прочитай `HANDOFF.md` и `[город]/[интеграция]/README.md`. Работаем только с этим клиентом. Сначала проверь тесты и не меняй другой проект без отдельного запроса».

Так новый чат начнёт с актуальной структуры и не будет использовать устаревшие файлы из `outputs/`.

### ТЗ: единый контракт совместимости

Цель — пять таблиц одинаково читаются внешней автозагрузкой и не требуют городских исключений в её коде. Рабочее ядро листов должно быть одинаковым во всех городах:

```text
телефоны:
A Model | B SimConfig | C MemorySize | D Color | E Price | F [пустой разделитель]
G Model | H SimConfig | I MemorySize | J Color | K RamSize | L Price

аймаки, макбуки, айпады, часы, наушники, пс, дайсон:
Title | Price
```

В `телефоны` левый блок — только iPhone; `RamSize` у него отсутствует. Правый блок — только Android, где `RamSize` заполняется, только если это значение есть у поставщика. `Country`/`Страна` не создаётся. Между блоками ровно одна пустая колонка `F`; Android начинается в `G`, не в `I`.

Неизвестная поставщику SIM-конфигурация не подменяется выдуманным `SIM + eSIM`. В эталонном ручном прайсе для такого случая используется техническое значение `Не знаю`; применять его в конкретном городе можно только после проверки, что именно его ожидает принимающая автозагрузка. Модель, память, RAM и цвет пишутся раздельно; в `Model` нельзя помещать полное название с объёмом, цветом, флагом, рекламным текстом или ценой. Для листов `Title | Price` название очищается от технических хвостов поставщика (`true/false`, SEO-ключи, дубли характеристик, флаги страны), но важные статусы товара, согласованные с клиентом, сохраняются.

Цена — число в рублях без текста. Перед записью каждый импортёр должен валидировать шапки и останавливать пересборку с понятной ошибкой, если они отличаются от контракта; нельзя молча записывать данные в сдвинутый блок. В отчёте пересборки должны быть отдельные счётчики: записано, пропущено из-за отсутствующего листа, пропущено из-за неполной конфигурации.

### Краснодар — прямая синхронизация цен в объявления (2026-08-24)

`Краснодар/RuStore/RuStoreCatalog.gs` больше не пересобирает ассортимент в таблице цен.
